# Response Flow

## Цель

Отклик должен быстро переводить просьбу из «сигнал висит» в реальное взаимодействие двух людей.

## Актуальный flow

1. Пользователь B открывает чужой запрос и нажимает `Откликнуться`.
2. Response публикуется в relay и становится виден автору A.
3. Если откликов несколько, A выбирает конкретного помощника.
4. После выбора открывается приватная координация в NIP-17 chat.
5. Автор при необходимости может отдельно передать точную геопозицию с явным подтверждением.
6. После помощи A отмечает запрос завершённым.
7. Приложение показывает короткое «Спасибо» и предлагает **необязательную** оценку 1–5.

## Что видит автор

- количество откликов
- возможность выбрать помощника
- статус запроса
- чат только с выбранным участником
- действие «Завершить»
- после завершения — возможность оценить помощь

## Safety

- точный адрес не нужен на стадии публичного запроса
- точная точка доступна только после match
- никакой встроенной предоплаты
- report/block доступны из важных поверхностей

## UX rule

Один этап — одно понятное следующее действие. Никакой формы ради формы и никакой протокольной терминологии в основном пути.
