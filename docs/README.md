# Мы Рядом Docs

This folder is the working memory of the project.

We use it to keep the product clear, decisions visible, and context stable between sessions.

## Core docs

- [vision.md](vision.md): why `Мы Рядом` exists and what kind of product it should become
- [mvp.md](mvp.md): the first version boundaries
- [product_principles.md](product_principles.md): rules that protect the product from complexity drift
- [ui_radar_concept.md](ui_radar_concept.md): the current direction for the main screen and interaction model
- [radar_mvp_screen.md](radar_mvp_screen.md): concrete MVP structure for the main radar screen
- [geo_mvp.md](geo_mvp.md): geolocation states, privacy, radius behavior, and stability rules for the MVP
- [request_creation_flow.md](request_creation_flow.md): how a user creates a help request in the MVP
- [response_flow.md](response_flow.md): how a nearby user responds to a request in the MVP
- [backend_mvp.md](backend_mvp.md): backend direction and first server scope for the MVP
- [nostr_mvp.md](nostr_mvp.md): how Nostr can carry requests, responses, and chat in the first connected version
- [nostr_event_schema.md](nostr_event_schema.md): concrete event kinds, tags, and mapping rules for the app
- [two_phone_test_flow.md](two_phone_test_flow.md): the first live relay-based test where one phone creates and another phone responds
- [trust_safety_mvp.md](trust_safety_mvp.md): minimum anti-scam, privacy, and trust guardrails for the first live version
- [decisions.md](decisions.md): important decisions and why we made them
- [session_log.md](session_log.md): short chronological log of what changed and what matters next

## How we use docs

- record decisions early
- keep docs short and honest
- prefer one strong note over many vague notes
- update the relevant doc when the product direction changes
- use the session log to avoid losing context between work sessions
