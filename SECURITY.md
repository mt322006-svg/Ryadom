# Security Policy

`Мы Рядом` связывает незнакомых людей, использует геолокацию и криптографические ключи. Уязвимости приватности и авторизации считаются security issues, а не «обычными багами».

## Сообщить об уязвимости

Если в GitHub для репозитория доступен **Security → Report a vulnerability**, используйте private vulnerability report.

Если private reporting недоступен, откройте обычный issue только с коротким заголовком вроде `Security contact requested` **без** exploit details, приватных ключей, точных координат пользователей и других чувствительных данных.

Не публикуйте рабочий exploit до исправления.

## Что особенно важно

Сообщайте приватно о проблемах, которые позволяют:

- получить или восстановить чужой private key
- увидеть plaintext приватного чата
- раскрыть точную геопозицию без явного согласия
- подделать автора request/state/chat
- обойти выбор помощника и читать чужую координацию
- принять malformed relay event так, что приложение падает или меняет чужое состояние
- сохранить чувствительный plaintext там, где политика проекта это запрещает

## Ключи и секреты

Никогда не коммить:

- `android/key.properties`
- keystore / `.jks` / `.keystore`
- Nostr private keys / nsec
- реальные чувствительные test fixtures

## Проверка изменений

Минимум перед merge:

```bash
flutter analyze lib test
flutter test
flutter build apk --debug
```

Изменения transport/privacy должны иметь тест, который доказывает требуемое свойство, а не только успешную сборку.
